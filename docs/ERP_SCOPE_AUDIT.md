**异常处理同样在 Agent 新开发。工程联络单用于解决异常，覆盖上报、评估、审批、整改、复验和关闭。** ERP 的异常与审批实现仅提供业务参考及原始证据；不调用旧异常处理流程。管理员使用同一 BPM 配置新模/改模设计上传、采购价格及工程联络单等模板，详见 BPM_AND_EXCEPTION_CONTRACT.md。

## 采购分工

| 范围 | 事实归属 | Agent 工作内容 |
|---|---|---|
| 原材、五金 | ERP | 新工具、统一页面、当前用户权限过滤、人工确认及接口回执；不另建同义价格/订单/收货事实 |
| 委外 | ERP | 复用现有采购及委外能力；设计/零件/工序/整套委外的差异继续逐项核对 |

| 试模料 | Agent 新增 | 设计标准及 ERP 模具/试模引用；设计与项目确认数量，核对客户供料，避免重复采购 |

用户进一步明确：采购下单、拆单复用 ERP 现有业务功能，不能因接入 Agent BPM 而重建。下单已有静态接口证据；拆单的具体入口、权限、幂等及副作用仍需逐项核验，尚未联调。辅材、办公用品和此前确认的试模料由 Agent 补齐所需业务；是否可调用通用下单能力按实际接口能力核对，订单事实只保留一处。

后续已定位钢料拆单/不拆单入口及其自动业务路由，见 ERP_ACTION_REVIEW.md。用户已确认两种路径都按 ERP 原流程调用；保留既有业务后续，不因其要求 autoRoute 而要求重做或拆除。这里的业务流程复用不改变 Agent 自建通用 BPM 的决定。

ERP 已出现 `auxiliary`、`office_supply`、`trial_material` 分类枚举（`purchase_request_detail_service.py:29`，前端 `purchase/request/index.vue:790`）。分类字段不能证明完整采购流程；按用户明确决定，三类新采购由 Agent 实现。ERP 已有真实记录保留其来源，不复制后再建单、再累计。

## 不能直接包装开放的接口例子

1. `contract_service.py:141～154` 存在付款记录新增、修改、删除方法。这不证明满足本项目的实付确认、不可覆盖更正及幂等要求；默认不提供覆盖历史付款的工具。
2. `trial_mold_service.py:97～126` 开始试模方法读到记录后更新状态，所读函数未完整体现装配完成和试模批准前置。须核对调用链并补充受控前置，不能据此重建试模台账，也不能据局部代码断言 ERP 全部不适用。
3. 装配开完工已存在实际校验和对账联动，重复实现会遗漏原有联动；应核对差异并复用。
4. ERP 工作流字段不能证明具备本项目要求的灵活 BPM；用户已明确不复用该审批流。现有执行 API 如硬性依赖 ERP 审批状态，应列为具体接口适配缺口，不能调用旧审批来绕过或直接写库。
