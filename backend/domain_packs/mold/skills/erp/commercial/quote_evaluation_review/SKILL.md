# 报价评估与加工方式核对

版本：1.0.0，新项目独立编写。

当用户询问某项目报价阶段是否已有成本核算、粗略工艺分析、工期估算、报价金额、最终加工方式、客户反馈、报价版本或后续合同依据时，先调用 `query_quote_evaluation_context`。

工具返回当前可见资料中的报价评估上下文，包括报价/承接记录、金额与证据文本、加工方式、项目档案执行方式、可见销售合同、可见整套委外合同，以及与计划相关的任务摘要。只能说“当前已见到/未见到”这些事实；不能把未见到解释为企业一定没有资料，可能是尚未接入、未授权、未确认或线索不唯一。

成本核算、技术工艺分析、项目工期估算和客户反馈应分别保留正式依据。若工具返回 `has_structured_cost_process_duration_breakdown=false` 或 `gaps`，需要明确说明当前只有综合证据或下游事实，不能声称已完成结构化报价评估。

用户明确要求形成或修改报价时，先读取 `query_quote_evaluation_context`。只有唯一项目、项目仍未正式开工、没有待处理报价版本，并取得 `quotation_workflow_options.id` 后，才能调用 `prepare_quotation_version`。必须使用本轮明确上传的客户图纸或资料，填写来源类型和稳定来源标识；内部加工必须分别填写成本金额及依据、粗略工艺分析和工期估算，整套委外还必须填写供应商价格、交期、其他要求及报价依据。新版本必须关联当前生效报价并连续增加版本号，不覆盖旧版。

`prepare_quotation_version` 只生成确认卡。本人确认后冻结本轮资料并提交 Agent BPM，审批生效前不能说报价已经发布、客户已收到或项目已承接。相同来源与同一文件重复处理复用原接收记录；相同文件由不同业务合法复用时不自动合并。

用户明确提供客户反馈并要求登记时，使用查询返回的当前生效报价 ID 调用 `prepare_quotation_feedback`。确认后只追加反馈事实；`ACCEPTED`、`REJECTED` 或 `REVISION_REQUESTED` 均不能替代承接/拒单 BPM，也不能自动生成新报价。

加工方式有三层含义：报价阶段初步方式、承接时确认的最终方式、执行中经审批变更后的当前有效方式。看到其中任一层都不能自动替代其他层；如工具返回加工方式冲突或多个方式，应要求核对当前有效依据。

读取阶段只做事实核对；任何写入都必须通过对应准备工具和本人确认。报价版本还必须经过 BPM 生效，客户反馈只追加已发生事实。承接/拒单、正式开工、加工方式切换和合同仍使用各自独立流程。
