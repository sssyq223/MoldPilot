# 合同上下文核对

当用户询问某个项目的销售合同、整套委外合同、合同号、付款节点、合同替代/追加、预计合同到达或合同是否已经生效时，先使用 `query_contract_context`。

使用规则：

- 先用项目 ID、项目编号/名称或合同号等线索定位项目；返回多候选时要求用户指定项目 ID，不要替用户选择。
- 只依据工具返回的合同、付款节点、不可变业务条款、替代关系和派生状态回答；不要把合同存在推断为承接完成、正式开工、验收通过或实际回款/付款完成。
- `cash_timing_analysis` 仅按经权限过滤且已结构化的客户收款节点、整套委外付款节点和已确认日期投影资金时序。`DATED_RISK` 可说明某日存在预计资金缺口；`DATES_INCOMPLETE`、`UNSTRUCTURED_INFLOW_TERMS` 或 `INFLOW_TERMS_MISSING` 必须同时说明证据不足。该分析不改变条款、不确认收付款，也不代替采购或财务审批。
- `late_expected_contracts` 只表示当前可见资料中预计日期已过且合同记录尚未生效/关闭，需要业务或财务人员核对；不要自行生成催办或更改项目状态。
- 查询请求只读，不上传合同、不做 OCR、不修改合同、不确认收付款。
- 用户明确要求登记、补录或提交销售合同/整套委外合同时，必须先使用 `query_contract_context` 确认真实项目、项目版本和可选审批流程，再使用 `prepare_contract_record` 准备合同登记建议。只能使用本轮明确关联，或用户在当前会话历史中明确指代且能够唯一确定的 PDF、图片或 DOCX 合同原件 `file_ids`；不能引用其他会话、其他用户或历史任务中的附件。历史附件在执行前必须重新校验权限并绑定到当前任务，多个候选必须要求用户选择。销售合同必须关联项目档案中的有效客户并填写签订日期、实际到达日期、合同交付日期、付款方式和编号映射依据；整套委外合同必须关联有效委外供应商并填写合同交付日期、付款方式和映射依据。海信销售合同按客户项目编号核对；海尔电子合同按已确认客户订单编号核对，海尔纸质合同按合同号关联；其他客户保留人工核对依据。合同卡同时冻结项目、内部模具号、客户订单和已生效正式开工单关联。付款节点金额合计不能超过合同金额；重复合同号、同项目同内容附件和项目版本变化必须阻断或重新核对。
- 原始合同使用 `relation_type=ORIGINAL`。追加合同使用 `ADDITION` 并关联仍有效的前序合同，但不迁移历史实收实付，审批生效后新旧金额同时有效。替代合同使用 `REPLACEMENT`，必须逐条列出前序版本链中全部实际回款或实际付款记录及其新合同节点，并提供财务分配依据；任何遗漏、重复、币种/客户/供应商不一致、节点溢出或并行替代都必须停止，不得由模型猜测。替代合同只有审批生效时才关闭前序合同，审批中和被驳回时不能改变旧合同。
- `prepare_contract_record` 只生成会话中的核对卡。本人确认后才将合同原件作为不可变第 1 版附件关联到合同材料并提交 Agent BPM；审批人从审批材料中查看被冻结文件。历史实收实付仍留在原始财务记录，通过不可变分配关系计入当前有效替代合同一次，不复制或覆盖原记录。审批生效前不视为正式合同，不确认收付款，不触发 ERP 合同执行。需要 OCR、合同文件正文识别、电子签、实际回款/付款、附件新版本或合同替代财务归属时，继续要求人工确认及专门流程。
- 用户明确要求登记整套委外合同签署扫描件、线下签署文件或签署状态证据时，先查询合同上下文确认真实项目、项目版本、已生效整套委外合同和供应商，再使用 `prepare_contract_signing_record` 准备签署证据登记建议。该工具只记录人工/导入/ERP 来源的签署证据；本人确认前不写入，不发起电子签署，不修改合同审批状态，也不确认收付款。
