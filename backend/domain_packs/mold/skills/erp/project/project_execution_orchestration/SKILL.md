# 项目执行链路协调

版本：1.0.0

目标：在项目基线计划之后，把设计/BOM/路线、采购与整套委外分支、制造质检、装配试模、交付签收和客户验收组织成一个可追溯的执行视图，先识别当前焦点，再按用户本轮明确要求展开对应业务事实。

适用条件：用户询问“项目执行到哪里”“计划之后各环节是否串起来”“设计采购制造装配交付进度”“当前卡在哪一步”“继续推进项目执行”或要求核对完整执行链路。

边界：本 Skill 是通用 Harness 上的模具 ERP 领域编排，不新增传统 ERP 页面，不把计划完成、试模通过、库存出库、客户签收和客户验收互相替代；不自动提交审批或写回 ERP。加工方式为整套委外时，以整套委外协同事实替代内部制造与内部装配主线，但仍保留独立交付验收核对。

步骤：
1. 先调用 `query_project_execution_context`，使用本轮给出的项目 ID、项目编号或名称定位唯一项目；多候选时要求用户选择，不得合并不同项目事实。
2. 按 `analysis.execution_lifecycle.stages` 展示各阶段真实状态。`UNAVAILABLE` 表示能力未授权或未分配，`NOT_APPLICABLE` 只表示工具已读到足以证明分支不适用的加工方式或设计路线。
3. 只读询问时，先给出 `current_focus`、明确阻塞或关注项以及下一步建议；不要为了“看起来完整”继续调用所有阶段工具。
4. 用户要求展开当前焦点时，只调用 `recommended_next_steps` 指向的一个阶段查询能力，读取完整事实、来源和限制。模型可在读取结果后再次选择下一能力，形成“协调器 → 阶段查询 → 结论”的多轮工具轨迹。
5. 用户明确要求办理操作时，必须切换到该阶段专用 Skill，重新查询真实 ID、版本、流程和材料；`query_project_execution_context` 的摘要不得直接作为任何写入参数。
6. 将制造任务完成、独立质检报告、试模通过、客户签收、客户验收和项目关闭分别陈述。没有正式业务事实就说明缺口，不做自然语言兜底或跨阶段推断。

失败处理：阶段查询失败时保留已取得的可见事实并说明具体失败阶段；权限或能力缺失时要求授权相应查询能力，不尝试通过其他工具绕过；加工方式冲突时提示核对承接、项目档案和最新审批依据。

输出要求：默认折叠工具过程，正文只给当前焦点、关键证据、阻塞项和下一步。用户展开后应能看到每轮能力调用及面向用户的进展说明。
