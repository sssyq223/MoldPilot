# 项目收尾链路协调

目标：把交付与客户验收、发票与客户回款、供应商付款与结算、异常关闭、全过程资料归档和最终项目关闭组织成一条可追溯的收尾链路，并严格区分正常关闭与终止结算。

适用条件：用户询问“交付后怎么结算关闭”“项目收尾到哪里”“能否关闭项目”“客户验收后还有什么”“终止结算完成了吗”或要求核对交付、财务、归档到最终关闭的完整链路。

边界：本 Skill 是通用 Harness 上的模具 ERP 领域编排，不新增传统 ERP 页面，不复制 ERP 财务或物流台账。交付、签收、验收、发票、回款、付款、结项事项、归档和关闭分别保留，不能用生产完工、发货、签收、单次回款或审批通过替代项目正式关闭。

步骤：
1. 先调用 `query_project_completion_context`，使用本轮给出的项目 ID、项目编号或名称定位唯一项目；多候选时要求用户选择，不得合并不同项目事实。
2. 按 `analysis.completion_lifecycle.stages` 展示各阶段真实状态、当前焦点、阻塞项和正常/终止分支。阶段能力未分配时显示 `UNAVAILABLE`，不得通过其他阶段推断。
3. 正常关闭须分别核对交付、适用客户验收、发票、客户回款、供应商结算、异常关闭和全过程归档；终止项目进入终止结算清单，交付和验收可按事实说明不适用，但必须保留处置、结算和归档依据。
4. 只读询问时先给出当前焦点、关键证据和阻塞项，不要继续调用全部阶段工具。用户明确要求展开时，只调用 `recommended_next_steps` 指向的一个阶段能力。
5. 用户明确要求办理时，切换到交付、财务或项目关闭专用 Skill，重新查询真实 ID、版本、清单、流程和依据；`query_project_completion_context` 的摘要不得直接作为写入参数。
6. `prepare_*` 只能生成待确认建议。本人确认、BPM 批准和领域命令成功应用是三个不同事实；没有正式回执时不得声称已确认收付款、已完成结算或已关闭项目。

失败处理：阶段查询失败时保留已取得的可见事实并说明具体失败阶段；权限或能力缺失时要求授权对应查询能力，不尝试通过其他工具绕过。结项清单与项目状态不一致时标记资料冲突并停止准备关闭建议。

输出要求：默认折叠工具过程，正文只给当前焦点、关键证据、阻塞项和下一步。用户展开后应能看到收尾阶段表、正常/终止分支和每轮能力调用。
