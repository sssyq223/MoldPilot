# 委外采购办理

只办理**委外采购员**在零件/模具委外采购支线上的动作：填我方报价与区间、选商发询价、超区间成交价、拒单后重选。不代办审批、接单、仓管、质检。

## 本角色可办阶段

| 阶段 | 办理工具 |
| --- | --- |
| 待采购填报价 | `prepare_erp_outsource_buyer_quote` |
| 待发询价 | `prepare_erp_outsource_inquiry_send` |
| 待填成交价 | `prepare_erp_outsource_final_deal` |
| 全部拒单 / 拒单后 | `prepare_erp_outsource_reselect` |

工序委外不走填价/询价/成交价。用户拿工序单来办这些动作时说明原因，不 prepare。

## 识别到填成交价必须弹出确认卡

用户说「NO.N 成交价填写 50000」「第2行填成交价 50000」「填写成交价:50000」且金额已给出时：

1. N 是「查看完整表格」第一列的 NO.，立刻 `prepare_erp_outsource_final_deal`，参数用整数 `board_row` 和 `final_deal_amount`。
2. 不要问联络号、采购号、订单号，不要向用户要报价单内部 id。报价单由该行已报加工商报价自动带出。
3. 该行不是待填成交价时说明当前进度，不要改锁同批次另一张。禁止只回待办表，禁止口头复述金额当确认。

## 识别到填报价必须弹出报价表

用户本轮是在**请求填写**我方报价（帮我填价格、填报价，并且金额已给出）时。句子里出现「填价格」但时态是已经填完（已经填了 / 填好了 / 填完了）时，那是在说填价已完成，不是再填一次。

1. **先锁定身份，再出表。** 必须确认模具号，并且确认订单号。待采购填报价尚未下单时，订单号按「尚未下单」，改用模具号 + 批次号 + 零件号锁定同一行。用户说「第N行」「第二行」或「NO.N」时，按「查看完整表格」第一列的 NO. 锁定那一行，不要在同批次里重数。同一批次、同一零件号有多张时，必须用这个行号，不要只说模具+批次+零件。待排列第一仍按待填价列表的第一张。缺模具号，或既没有订单号、又凑不齐批次号+零件号时：只澄清要哪一单，**禁止**只回待办看板表，也**禁止** prepare。
2. **身份锁定后立刻**调用 `prepare_erp_outsource_buyer_quote`，弹出与 ERP 填价页同类的**报价确认表**（核算价、我方报价、直接接单上限，以及订单号/模具号/批次号/零件）。这就是确认卡。不要用 Markdown 表格代替确认卡，不要只 query 看板。
3. 总价格填 `our_quote_amount`，上限填 `auto_accept_max_amount`。用户点名零件时必须带 `part`（如 PH-01）。同一模具同一批次常有多张询价，只传模具+P1 会命中多张。
4. 禁止编造 `prepare_project_quote`。禁止口头复述金额当确认。本人在确认卡上确认后才写入 ERP。

## 工作流

```text
先锁定 模具号 +（订单号 或 批次号+零件号）+ 当前分站
  → 识别到填报价且金额齐全
  → prepare_erp_outsource_buyer_quote 弹出报价表确认卡
  → 本人确认后才调 ERP
```

只问数量或待办时先 query，不要 prepare。看板已经列出待填价行、用户已点名零件并给出报价和上限后，立刻 prepare，不要再调 `query_erp_outsource_order_progress`，不要再画一遍待办表。同一模具多单未点名零件时列出候选的订单号、模具号、批次号、零件号，等用户选定后再 prepare。尚未下单时用单一批次号；合并多批次的询价要用表格里的完整批次号。用户说第N行或 NO.N 时，按完整表格第一列锁定；同批次另一张不能代替。不要只用口里的 P1。禁止使用内部数字 id。填价确认写入后，当前分站才会变成待发询价；选加工商、发询价是下一步，另走 `prepare_erp_outsource_inquiry_send`。用户追问上一轮失败原因时，用已有查询结果解释，不要再查一遍整表。

1. 状态不对、缺金额时只澄清，不 prepare。
2. 确认卡必须写清订单号（或尚未下单）、模具号、批次号、零件、报价表金额。用户要发询价时按整句意图认：填价已完成 + 发给加工商/厂家/可以发，就是发询价，不要因为句子里有「填价格」三个字就改去填价。说「待发询价这单 / 给加工商发询价单」时，按完整表格里那张待发询价锁定（可能是 NO.2，不是表上第一行），立刻 `prepare_erp_outsource_inquiry_send` 并**省略 suppliers**，用该单 ERP 已匹配名单。不要改去填表上另一张待填报价。「第N行 / NO.N」按完整表格该行锁定。该行不是待发询价时说明当前进度，不要改锁同批次的另一张。禁止再口头问「确认下一步办理」，禁止编造「华兴机械」等名称，禁止把「和兴」改写成「华兴」。用户点名时必须用查询结果里的编码或全称。禁止内部数字 id。用户否认则停。
3. 禁止口头宣布已写入。以确认卡回执和 ERP 返回为准。

## 跨角色交接

- 加工商报价后：报价合计 ≤ 直接接单上限时 ERP 免审定标，成交价可以空着，单子到待接单（加工商办理）。报价合计 > 上限时停在待填成交价，必须填成交价再走主管王群、总经理李辉审批；空成交价不是漏填，是还没定标。
- 零件/模具拒单后 ERP 把工单标 rejected、询价回到 draft，本地应显示待发询价（不是待接单，也不自动再走成交价审批）。采购重选加工商后发询价。工序拒单由 ERP 自动转下一家；只有队列耗尽才重派。
- 不代办加工商报价/接单，不代批下单审批。

## 边界

采购主管/总经理审批、加工商报价/接单、仓管发料入库、质检不在本 Skill。整套委外合同用 `full_outsource_review`。
