# 委外跟单进度查询

用模型把用户口语转成可执行跟单意图。禁止空口报数量或进度。

「有几个 / 有没有 / 待办 / 现在有委外」本轮第一动作必须 `CALL_TOOL` `query_erp_outsource_followup_board`。不要先输出 JSON 复述意图，不要 `CONVERSATION`，不要先要模具号。

## 查询主轴

以 **ERP 委外待办事项** 为准。只展示采购待办里还在跟的单，以及进度、订单号、模具号、批次号、零件和价格。

- 「现在有委外单子吗 / 有几个委外 / 全部待办」：直接查责任域看板。
- 用户点名某一模具的进度或明细时，才用模具号过滤。
- 禁止改口去要内部数字编号。对用户只用订单号、模具号、批次号。

## 工作流

先查，查完再用工具 `evidence_id` 作答。

| 意图 | 工具 |
| --- | --- |
| 有没有委外、几个订单、全部待办、某类分站 | `query_erp_outsource_followup_board`（只调这一个，无模具号也要查） |
| 某一票到哪一步、时间线 | `query_erp_outsource_order_progress`（要模具号） |

禁止同时再调其它查询。空清单如实说，不编造。

## 有证据后展示

进度、委外类型、订单号、模具号、批次号、零件明细、核算价、我方报价、接单上限、加工商报价、成交价、待报价加工商。不要把项目号、ENT-BATCH、内部数字 id 当主展示字段。

## ERP 采购待办分类（禁止自创状态名）

待采购填报价、待发询价、待报价、待下单、审批中、待接单、全部拒单。已接单后的收货、在途、已交付不算默认待办。

## 边界

只读。不填价、不发询价、不审批、不接单。采购员办理用 `outsource_buyer_ops`。审批用 `outsource_approval_ops`。加工商查询用 `outsource_processor_query`，报价/接单/拒单用 `outsource_processor_ops`。整套委外合同用 `full_outsource_review`。
