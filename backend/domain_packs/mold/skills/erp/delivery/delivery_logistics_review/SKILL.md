# 交付物流上下文核对

版本：1.0.0，新项目独立编写。

当用户询问某项目的出厂检验、入库/出库、发货、物流路线、承运商、物流报价、客户签收、客户验收、验收不通过整改或交付归档时，先调用 `query_delivery_logistics_context`。

工具返回当前可见的项目交付计划节点、正式订单发货、仓库收货、入库检验、库存移动、试模结果、Agent 出厂自检/放行记录、结项清单、工程联络异常和 `analysis.erp_delivery_execution` 中的 ERP 履约事实。只能说“当前已见到/未见到”对应事实；未见到不能解释为企业没有发生，可能是 ERP 出入库/发货模块尚未接入、用户未授权、资料未补录或线索不唯一。

ERP 履约记录只表示原系统存在履约事实，必须保留其 `source_ref`、`source_endpoint`、`as_of` 和状态。它可以把交付阶段识别为已开始，但不能替代 Agent 本地供应商发货明细、客户签收、客户质量验收或项目关闭；ERP 异常记录应作为交付阻塞提示。

必须区分供应商发货、仓库收货、入库检验、Agent 出厂自检/放行、出库、客户签收和客户质量验收。供应商发货不等于客户签收；试模通过不等于出厂放行或客户验收；客户签收不等于质量验收合格；单次验收也不等于项目关闭。

试模通过后登记出厂自检或放行使用 `prepare_outbound_release`，必须引用真实项目版本和试模通过记录，并提供检查依据与来源单号。失败或有条件通过必须填写问题和整改期限；整改复验只能通过 `previous_record_id` 引用当前未闭环记录，不创建分叉。该工具只写入 Agent 不可变事实，不写回 ERP、不自动出库或发货。执行/收尾上下文若已见试模通过但没有自检放行合格依据，会把交付阶段标为 `BLOCKED`；最新放行失败则为 `NEEDS_ATTENTION`。

发运后已取得客户签收原件或明确签收依据时，使用 `prepare_customer_delivery_signature` 登记 Agent 客户签收事实。必须填写真实项目版本、签收日期、签收/交付单号、签收人和依据；如有原件，只能关联当前任务本人上传并绑定的文件。本人确认后才保存 `DELIVERY` 签收记录，不写回 ERP，也不把它解释为移模时间、质量验收、回款或项目关闭。按客户签收日期维护移模时间仍使用财务工具 `prepare_mold_transfer_receipt`，两类记录分别保留。

登记客户质量验收使用 `prepare_customer_acceptance`，本人确认后才保存。整改复验必须通过 `previous_acceptance_id` 引用该验收链当前末条记录，保持同一项目及签收依据，并核对前次问题、结果和原件；查询的 `recheck_candidate_ids` 提供可继续核对的真实记录标识。前次记录已有后续复验时重新查询，不创建分叉。另一条初验通过或没有前次关联的历史复验不能消除已有未解决失败；正常结项的清单完成或“不适用”也不能绕过此缺口。责任、工程联络、扣款、工期和合同变化仍分别按对应流程办理。

办理路线或报价时仍必须先调用 `query_delivery_logistics_context`，取得真实项目、当前版本和已有路线/价格事实。不得把用户口述、附件文件名或模型推断直接写入。

仓库确认固定路线或模具实际路线时使用 `prepare_logistics_route`。固定路线不绑定项目；模具实际路线必须绑定查询得到的项目和当前版本。路线必须包含地点、承运商、车型、重量、运输方式、计价单位、含税方式、有效期和可追溯来源。工具只准备确认卡，本人确认后才登记路线；不确认发货、客户签收或验收。

采购价格审批人确认物流报价或项目本次结算价格时使用 `prepare_logistics_quote`。报价有效期不得超过系统适配参数（默认 183 天）；多家比价必须至少两家并填写参与方与比较结论摘要。项目结算价必须绑定真实项目当前版本，同时保留报价/询比议价依据与对账依据。本人确认后登记生效价格，但不代表物流单、实际费用、付款或财务对账已经完成。

没有相应权限、真实路线、询比议价材料或对账依据时，应说明缺口并停止准备；不得补造承运商、路线、价格、比价家数或回执。ERP 仓储、出入库、发货和财务执行仍以对应正式系统回执为准。
