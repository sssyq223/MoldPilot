# 装配试模上下文核对

版本：1.0.0，新项目独立编写。

当用户询问某项目的装配齐套、钳工主管、装配工单、装配开工/完工、试模申请、试模资源或机台、试模报告、试模未通过整改、装配/试模异常工程联络时，先调用 `query_assembly_trial_context`。

当用户明确要求登记已生效装配任务的开工或完工回执时，必须使用查询结果中的真实项目版本和装配任务 ID，再调用 `prepare_assembly_execution` 准备确认卡；本人确认后才追加 Agent 执行回执，不替代 ERP 装配工单或现场执行。

当用户明确要求登记已生效试模申请的通过或未通过结论时，必须使用查询结果中的真实项目版本和试模申请 ID，再调用 `prepare_trial_result` 准备确认卡。未通过必须关联真实工程联络单；试模报告原件只能引用当前任务中本人上传并绑定的文件。本人确认后才追加试模结论，不能把通过直接当作出厂放行，也不能用未通过结论代替整改复验。

工具返回当前可见的项目计划节点、设计 BOM 与路线、装配任务下发、装配执行确认、试模申请、试模结果和工程联络异常上下文。只能说“当前已见到/未见到”对应事实；未见到不能解释为企业没有发生，可能是 ERP 装配/试模模块尚未接入、用户未授权、资料未补录或线索不唯一。

同时读取 `analysis.erp_manufacturing_execution` 中按项目号/模具号查询到的 ERP 制造工单、工序报工和质检任务/结果；其中与装配、组立、钳工或试模相关的记录只作为原系统证据入口，保留 `source_ref`、`source_endpoint` 和 `as_of`，不复制为 Agent 装配或试模业务对象，也不把报工或质检结果自动解释为齐套、试模通过或出厂放行。质检不合格/部分合格仍需关联工程联络和复验依据。

装配齐套必须区分计划节点、设计路线、采购/委外/加工完成、ERP 齐套检查和钳工主管确认。不得只凭计划任务或总体百分比认定可以装配，也不得把装配完成等同于试模完成。

试模通过只代表当前可见的试模结论，不等于客户验收、出厂放行、发货完成或项目关闭。试模未通过时，应提醒关联工程联络单、整改责任任务和重新验证依据。

本技能只读，不下达装配工单、不登记装配开完工、不安排试模、不登记试模结果、不关闭异常、不修改 ERP 装配或试模执行数据。需要办理时必须进入对应准备工具、ERP 执行能力或人工确认流程。
