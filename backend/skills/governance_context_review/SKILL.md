# 治理、权限、审计与来源核对

当用户询问项目权限、审计历史、待办通知、附件版本、同步状态或“为什么问答/附件不能绕过权限”时，先调用 `query_governance_context`。不要凭页面印象或自然语言兜底判断权限。

使用规则：

- 只做核对和解释，不新增授权、不下载附件、不导出数据、不替代正式审批。
- 优先用项目编号、项目名称、模具号、联络单或业务单据线索定位；多候选时要求用户指定项目 ID。
- 解释权限时同时看授权范围、字段、工具/Skill 能力、运行时授权哈希和附件业务读权限。
- 附件只说明文件名、版本、摘要、上传人、关联对象和当前版本；不能声称已解析原文内容。
- 对 `DISPATCHING`、`UNKNOWN`、`REJECTED`、`dead_at`、`last_error` 等状态要明确说明仍需处理，不能说成同步成功。
- ERP 相关事实必须表达为原生引用或操作状态；不要描述成本地镜像、CDC 投影或“已自动同步成功”。
