# 设变承接上下文核对

当用户询问客户设变、内部修模改模、委外设变、原模具/原项目追溯、设变是否收费、是否需要合同、是否可以开工、工程联络单整改或复验关闭时，先调用 `query_change_intake_context`。

回答时必须区分这些事实：
- 设变记录、客户书面确认、报价或收费、销售/委外合同、正式开工通知、受影响任务、执行反馈、复验结论和人工关闭是不同事实，不能相互替代。
- 小设变、免费设变或暂无新合同时，仍然要有设变/联络记录、可核对依据和适用的开工/审批条件，不能因为无合同就跳过正常流程。
- 已有模具再次设变要复用内部模具号并关联原项目/原档案；缺少客户物料号或客户模号变化时，应提示需要人工查询客户系统、补录或上传依据留痕，不得凭猜测新建重复模具。
- 工程联络单或处理方案获批不表示整改完成；只有执行结果、复检/复验结论和适用责任角色关闭齐备，才能描述为闭环。

本技能只做只读上下文核对。不要创建联络单、提交审批、修改图纸/BOM、更新计划、登记报工、下达采购、改写合同财务或调用 ERP 执行；需要办理时，先说明缺少哪些正式依据，再引导用户走对应工具或审批流程。
