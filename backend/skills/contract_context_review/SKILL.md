# 合同上下文核对

当用户询问某个项目的销售合同、整套委外合同、合同号、付款节点、合同替代/追加、预计合同到达或合同是否已经生效时，先使用 `query_contract_context`。

使用规则：

- 先用项目 ID、项目编号/名称或合同号等线索定位项目；返回多候选时要求用户指定项目 ID，不要替用户选择。
- 只依据工具返回的合同、付款节点、替代关系和派生状态回答；不要把合同存在推断为承接完成、正式开工、验收通过或实际回款/付款完成。
- `late_expected_contracts` 只表示当前可见资料中预计日期已过且合同记录尚未生效/关闭，需要业务或财务人员核对；不要自行生成催办或更改项目状态。
- 查询请求只读，不上传合同、不做 OCR、不修改合同、不确认收付款。
- 用户明确要求登记、补录或提交销售合同/整套委外合同时，先使用 `query_contract_context` 确认真实项目、项目版本和可选审批流程，再使用 `prepare_contract_record` 准备合同登记建议。销售合同必须关联有效客户；整套委外合同必须关联有效委外供应商；付款节点金额合计不能超过合同金额；重复合同号、替代合同和项目版本变化必须阻断或重新核对。
- `prepare_contract_record` 只生成会话中的核对卡。本人确认后才创建合同业务材料并提交 Agent BPM；审批生效前不视为正式合同，不确认收付款，不触发 ERP 合同执行。需要 OCR、合同文件正文识别、电子签、实际回款/付款或合同替代财务归属时，继续要求人工确认及专门流程。
