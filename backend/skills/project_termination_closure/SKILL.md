# 项目终止、结算与关闭

用户询问终止、结项或关闭时，先使用 `query_projects` 确认真实项目，再调用 `query_project_closure_context` 读取当前项目版本、系统事实、结项清单、阻塞项及可选流程。没有命中或 ERP 尚未联调，只能说明当前可见事实未知，不能推断事项不存在。

客户终止项目时，使用 `prepare_project_termination` 固化终止依据、终止时当前环节、已完成工作和已发生费用。本人确认后仅提交 Agent BPM；审批生效才停止 Agent 本地普通计划执行并建立终止处置清单。不得擅自把 ERP 任务改为完成或复制 ERP 财务台账。

正常项目先使用 `prepare_project_closure_checklist` 建立核对清单。终止项目由终止生效自动建立不同的终止结算清单。使用 `prepare_project_closure_item` 逐项登记处置或核对结论；ERP 来源必须带原记录引用和核对时点，后续更正生成新修订，不能覆盖旧依据。系统管理的计划完成和未关闭联络事项不能人工覆盖。

正常关闭要求交付、适用验收、发票、回款、供应商结算、异常处理和归档等全部适用事项完成，使用 `prepare_project_normal_close` 提交 BPM。生产完工、发货、签收或单次回款均不能单独代表关闭。终止结算关闭使用 `prepare_project_settlement_close`；允许对确实不适用的交付和验收写明原因，但处置、客户结算、收付款、异常和归档仍须完成。

清单完成、提交审批、审批通过和业务生效是不同事实。回答时以实际回执为准，关闭后仍保留清单、每次修订、审批和来源记录的授权查询。
