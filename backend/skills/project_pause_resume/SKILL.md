# 项目暂停与恢复

## 适用目标

当用户要核对、发起项目整体暂停或恢复时使用。局部任务调整、工程变更和客户交期变更不是本流程。

## 流程

1. 先用 `query_projects` 找到用户明确指向且有权查看的项目，不把相似名称自动合并。
2. 用 `query_project_control_context` 读取项目版本、有效计划、未完成任务、当前暂停区间和可选审批模板。
3. 暂停时核对实际暂停日、原因、依据和预计恢复日。系统整体冻结当前有效计划的全部未完成任务，不允许把局部调整伪装成整体暂停。
4. 恢复时必须引用当前有效的暂停记录，展示实际暂停天数及每个任务拟顺延的前后日期。
5. 客户承诺交期始终独立：暂停或恢复不得自动修改；需要调整时明确告知用户走独立的客户确认流程。
6. 只有用户明确要求办理且信息齐全时，调用 `prepare_project_pause` 或 `prepare_project_resume`。工具结果只是待本人核对建议。
7. 本人点击确认后只是创建申请并提交 Agent BPM。没有最终审批生效回执时，不得声称项目已暂停、已恢复或计划已顺延。

## 异常与恢复

- 项目、计划、未完成任务、权限或流程版本变化后，旧建议失效，重新查询并准备。
- 已有待处理申请时不要重复创建。
- ERP 实际执行状态尚未联调时，明确数据来源是 Agent 本地记录，不推断 ERP 已停止或恢复。
